# Update checklist

Most of the data upkeep is automated: the weekly collector refreshes the code
snippets, `yarn validate:data` catches broken data, and the dependency workflow
reports outdated packages. This page lists what is **still manual**, in the
order to go through it when updating the project.

!!! tip "For coding agents"
    When asked to *update* the project, walk this page top to bottom, report
    what each step found, and commit fixes step by step with `yarn verify`
    green. Add a step here whenever something new turns out to need a human.

## 1. Data health

```bash
yarn validate:data --verbose
```

Triage every warning: `orphan-snippet` (a resource was renamed or deleted),
`incomplete-field`, `icon-not-found`, `foreign-content`... The rules and their
meaning are listed on the [admin dashboard](../features/admin.md) page.

## 2. The weekly snippet pull request

`run-code-collector.yml` opens a pull request on the
`automated-code-snippet-update` branch every Sunday. Read its diff before
merging: the collector takes the *first* Terraform block of the provider docs,
which is sometimes a data source or a `provider` block rather than the
resource itself.

## 3. New services

The datasets only grow by hand. For each provider, compare its catalogue with
the table and add what is missing with `yarn add:resource`:

- **Terraform registry**: list the resources of the provider and diff them with
  the dataset (`hashicorp/azurerm`, `hashicorp/aws`, `hashicorp/google`,
  `ovh/ovh`, `scaleway/scaleway`).
- **Renamed or rebranded products**: Azure in particular renames services
  (Azure AI Foundry absorbing Azure OpenAI and AI Studio, Microsoft Fabric,
  Microsoft Entra...). Update the name and description, keep the id so
  existing links keep working.
- **Naming conventions** (`slug`, `length`, `restrictions`) are never exposed
  by Terraform: take them from the provider documentation (for Azure, the
  *Naming rules and restrictions* page and the CAF abbreviations).

## 4. Retired services

- Resources whose `terraformUrl` is pinned to an old provider release instead
  of `/latest/`: the resource sheet flags them, and they usually mean the
  resource was removed from the provider. Decide whether to keep, replace or
  delete the resource.
- Look for *deprecated* / *superseded by* notices on the provider docs of the
  resources you touch.

```bash
grep -n "registry.terraform.io/providers/[^/]*/[^/]*/[0-9]" src/app/data/*.ts
```

## 5. API versions of the Azure snippets

The Bicep and ARM tabs show the API version of each snippet. Look for:

- **preview** API versions that now have a stable release;
- API versions that are several years old.

```bash
grep -l "preview" public/azure/code/bicep/*
```

The snippets are regenerated by `python/bicep-collector.py` and
`python/arm-collector.py`, so fix the source (the `resource` / `entity` fields
of `azure.ts`) rather than the generated file.

## 6. Icons

- `yarn icons:sync --update` picks up the latest theSVG release; map new AWS
  and Google Cloud resources in `scripts/icon-map.json` first (the script
  lists the resources without an icon).
- OVHcloud and Scaleway have no icon pack yet: look again for an open source
  one.
- Run `yarn validate:data` to catch broken paths.

## 7. Dependencies

```bash
yarn check:deps
```

Upgrade by steps (see the dependency notes in `TODO.md`), never with
`npm install`.

## 8. Documentation

- Resource counts per provider in `docs/index.md` and
  `docs/features/providers.md`.
- Screenshots in the documentation when the layout changed.
- `yarn update:credits` (CI fails when the credits page is stale).
